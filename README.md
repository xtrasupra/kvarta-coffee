# Кварта — свежая обжарка кофе

Учебный лендинг вымышленной мастерской в Минске. React на GitHub Pages,
FastAPI и SQLite на PythonAnywhere; сохранённые заявки отправляются в Telegram.

- Сайт: https://xtrasupra.github.io/kvarta-coffee/
- API: https://xtrasupra.pythonanywhere.com/api/health

## Локальный запуск

Во `frontend` выполнить `npm ci` и `npm start`. В файле
`frontend/.env.development.local` указать `REACT_APP_API_URL=http://127.0.0.1:8000`.
Не создавать `.env.local` с локальным адресом: CRA читает его и при production-сборке,
и он перекрывает `.env.production`.

В `backend` создать виртуальное окружение, установить зависимости из
`requirements.lock.txt` и заполнить локальный `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
DB_PATH=data/leads.sqlite3
ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

Запуск из `backend`: `python -m uvicorn main:app --reload`.

## Публикация и хранение заявок

Фронтенд публикуется командой `npm run deploy` из `frontend`.
Публичный адрес API хранится в `.env.production`; секретов там нет.
На PythonAnywhere в серверном `.env` нужно разрешить origin
`https://xtrasupra.github.io` без пути `/kvarta-coffee`.
Для бесплатного аккаунта внешний HTTPS-доступ использует
`HTTPS_PROXY=http://proxy.server:3128`.

SQLite выбрана для небольшого потока заявок: отдельный сервер БД не требуется,
проверка дубля и вставка выполняются одной транзакцией `BEGIN IMMEDIATE`.
Номер нормализуется на сервере; повторный номер в течение 600 секунд не создаёт
новую запись. Журнал SQLite работает в режиме `DELETE`, совместимом с выбранным
хранилищем. На сервере требуется один процесс приложения и постоянный путь к БД.

Очередь Telegram хранится в самой БД и повторяет неудачные попытки отправки.
При потере подтверждения Telegram возможен повтор уведомления с тем же ID;
сама заявка в SQLite остаётся одной. Секреты и база исключены из Git.
Поддержка ASGI на PythonAnywhere экспериментальная; срок действия бесплатного
приложения нужно своевременно продлевать. Это демонстрация, не коммерческий сервис.

## Работа с ИИ и проверки

Пользователь создал и уточнял макет, принимал решения о дизайне и стеке,
пошагово собирал проект с объяснениями ИИ. При проверке публикации ИИ обнаружил:
локальный `.env.local` перекрывал production-адрес API, сервер не разрешал origin
GitHub Pages, а проверка длинного комментария обращалась к переменной до объявления.
Адрес проверялся в опубликованном JS, CORS — запросом OPTIONS к API.

Регрессионные проверки формы: `npm test -- --watchAll=false --runInBand`.
Проверка сборки: `npm run build`.

17.10.2026 проверены опубликованная сборка и CORS с origin GitHub Pages:
два одновременных POST создали одну заявку, неверный номер получил HTTP 422,
UTM сохранились в SQLite, Telegram подтвердил доставку с первой попытки.
После перезапуска API заявка сохранилась и повторный POST был распознан как дубль.
Два регрессионных теста формы и production-сборка прошли.
Проверка через браузерный инструмент завершилась таймаутом; визуальная проверка
не выдаётся за выполненную.

Lighthouse, оптимизация тяжёлых изображений
и полная проверка визуального соответствия макету остаются отдельными этапами.
